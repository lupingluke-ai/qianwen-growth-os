# 前端设计验收清单

用于每次视觉或交互改版的发布前检查。重点是让高频数据操作保持轻量，同时在阶段性成果上保留品牌记忆点。

## 品牌与令牌

- [ ] 不使用未经品牌团队交付的 Logo、3D Logo 或字体文件。
- [ ] 主行动使用 `#41D87E` 或 `#2DD370`，文字使用近黑色；不在该绿色上放白字。
- [ ] 标题、正文、数字字体分别走 `--font-display`、`--font-ui`、`--font-metric`，缺少授权字体时回退正常。
- [ ] 圆角、阴影、间距均引用语义令牌，不为单页新造近似值。
- [ ] 60° / 120° 几何语言只用于成长面板、阶段封面、空/成功状态；表格和表单保持克制。

## 页面与响应式

- [ ] 桌面端检查 1280、1440、1920 宽度；主要行动在首屏可见，数据列不被截断。
- [ ] 移动端检查 390、430 宽度；表格转为可点击的摘要卡，详情进入抽屉或弹窗。
- [ ] 顶部导航在窄屏可展开、可关闭；当前页面状态清楚。
- [ ] 任何触控操作目标不小于 44 × 44 px。
- [ ] 空、加载、错误、成功四种状态均有下一步行动和明确文案。

## 可访问性与交互

- [ ] 从页面顶部可通过“跳到主要内容”绕过重复导航。
- [ ] 所有键盘焦点可见；Tab 顺序、Esc 关闭弹窗、弹窗焦点闭环可用。
- [ ] 图标按钮均有中文可访问名称；装饰图没有重复朗读。
- [ ] 状态变化通过 `role=status`、`role=alert` 或 `aria-live` 被读屏识别。
- [ ] 正文、标签和禁用状态对比度满足至少 WCAG AA；不能只靠颜色传递状态。
- [ ] 使用 `prefers-reduced-motion` 时，动画和脉冲效果不影响操作。

## 视觉回归与发布

- [ ] 用真实数据检查最长姓名、长链接、0 条记录、10 级层级等边界情况。
- [ ] 对“我的成长、能力阶梯、评审中心、团队”四页进行桌面和移动端截图对比。
- [ ] 验证主按钮、字段聚焦、错误提示、状态标签在各页一致。
- [ ] 新增图片压缩且提供有意义 alt，或明确标记为装饰图。
- [ ] 执行构建、类型检查与关键路径人工回归；记录已知的存量静态检查问题。
